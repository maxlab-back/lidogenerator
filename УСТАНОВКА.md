# Запуск лидогенератора на новой машине

Инструкция для любого Linux: Ubuntu, Debian, Fedora, openSUSE, Arch, Alpine, любой сервер
или контейнер. Всё, что нужно, скрипт доставит сам.

---

## Коротко

```bash
git clone https://github.com/maxlab-back/lidogenerator.git
cd lidogenerator
./start.sh
```

Откроется `http://127.0.0.1:8765`. Всё.

Если файл не запускается («Permission denied») — запусти через оболочку:

```bash
sh start.sh
```

---

## Что нужно от машины

| Нужно | Пояснение |
|---|---|
| Linux | Любой дистрибутив. `bash` не нужен — хватает `/bin/sh` (проверено на busybox из Alpine) |
| Интернет | Для установки пакетов и, собственно, для поиска компаний |
| ~500 МБ на диске | Виртуальное окружение с зависимостями |
| Python 3.10+ | **Ставить не надо** — если его нет, скрипт поставит сам |
| Права root | Нужны, только если Python или `pip` придётся доустанавливать. Скрипт спросит разрешение |

## Шаг 1. Забрать проект

**Через git:**

```bash
git clone https://github.com/maxlab-back/lidogenerator.git
cd lidogenerator
```

Ключей в репозитории нет и быть не должно — он публичный. Их вводят один раз на вкладке
«Ключи» (шаг 3) или переносят файлом `.env` с рабочей машины:

```bash
scp "Лидогенератор/.env" user@сервер:~/lidogenerator/.env
```

**Или копированием папки** целиком — так переедут и ключи (`.env`), и накопленная база лидов:

```bash
rsync -av --exclude .venv "Лидогенератор/" user@сервер:~/lidogenerator/
```

> Папку `.venv` копировать не нужно и даже вредно: внутри зашиты пути старой машины.
> Скрипт соберёт её заново.

---

## Шаг 2. Запустить

```bash
./start.sh
```

Скрипт по шагам проверит и доделает всё сам:

```
1. Python
  ✓ Python 3.13.15 — /usr/bin/python3.13

2. Окружение
  ✓ виртуальное окружение создано

3. Зависимости
  ✓ установлены
  ✓ lxml есть (быстрый разбор HTML)

4. Ключи (.env)
  ✓ .env на месте

5. Chromium (для сайтов на JavaScript)
  ✓ найден: /usr/bin/chromium

Запускаю
Лидогенератор запущен: http://127.0.0.1:8765/
```

Первый запуск занимает 20–40 секунд (ставятся пакеты), дальше — мгновенно.

Что произойдёт, если чего-то не хватает:

- **нет Python или он старый** — скрипт предложит поставить его командой твоего дистрибутива
  (`apt`, `dnf`, `zypper`, `pacman`, `apk`) и выполнит её через `sudo` после твоего «да».
  На Debian 11, Ubuntu 20.04 и RHEL 9, где обычный `python3` — это версия 3.9, он сам запросит
  пакет посвежее (`python3.12`, `python3.11`);
- **нет `venv` или `pip`** — предложит доустановить, а если нельзя, соберёт всё системным
  Python в домашнем каталоге и всё равно запустится;
- **нет Chromium** — предупредит и поедет дальше: без него теряются контакты только с тех
  сайтов, которые рисуются скриптами;
- **нет `.env`** — создаст пустой. Поиск будет работать через бесплатный DuckDuckGo, но
  **без Google Карт** (см. следующий шаг).

### Полезные флаги

```bash
./start.sh --check        # диагностика: пакеты, ключи, остаток кредитов, база, порт
./start.sh --setup        # только собрать окружение, без запуска
./start.sh --yes          # ничего не спрашивать (для серверов и скриптов)
./start.sh --recreate     # пересобрать окружение с нуля, если что-то сломалось
./start.sh --port 9000    # другой порт
./start.sh --cli          # нишевый режим (подоконники/откосы) вместо веб-интерфейса
./start.sh --install      # ярлык в меню приложений и автозапуск при входе в систему
./start.sh --uninstall    # убрать ярлык и автозапуск
```

## Шаг 3. Ключи

Открой вкладку **«Ключи»** в интерфейсе. Там все девять сервисов: у каждого написано,
что он даёт, сколько стоит и где взять ключ. Вставляешь ключ → **«Сохранить и проверить»**:

- ключ сохраняется на сервере в файле `.env`;
- тут же проверяется живым запросом (Serper покажет остаток кредитов, Apify — тарифный план,
  Telegram — имя бота);
- начинает работать **сразу**, перезапускать сервер не нужно.

Если папку копировали целиком, ключи уже на месте и делать тут нечего.

### Что работает без каких ключей

| Ключ | Что даёт | Что будет без него |
|---|---|---|
| `SERPER_API_KEY` | Google Карты + быстрый поиск сайтов | **Карт нет совсем.** А это около трети всех компаний — те, у кого нет сайта, только карточка с телефоном. Сайты будут искаться бесплатным DuckDuckGo |
| `ANTHROPIC_API_KEY` | ИИ читает сайт и решает, та ли это компания | В выдаче заметно больше каталогов и агрегаторов |
| `APIFY_TOKEN` | Яндекс Карты и 2ГИС | Останутся только Google Карты |
| `DADATA_API_KEY` | ИНН, юрлицо, статус, выручка | Ликвидированные и банкроты не отсеиваются |
| `GOOGLE_CSE_KEY` + `..._CX` | Бесплатный запасной поиск (100 запросов в день) | Когда кончатся кредиты Serper, сайты пойдут через DuckDuckGo |
| Telegram, Битрикс24, amoCRM | Уведомления и выгрузка в CRM | Лиды выгружаются в Excel |

Без единого ключа лидогенератор тоже работает — на DuckDuckGo и обходе сайтов.

## Доступ для команды по сети

По умолчанию сервер слушает только эту машину. Чтобы открыть доступ коллегам, сначала
заведи пользователей — без них наружу он не выйдет:

```bash
./start.sh --add-user ivan       # пароль спросит; от 8 символов
./start.sh --users               # список заведённых
./start.sh --host 0.0.0.0 --no-browser
```

Теперь на вход требуется пароль. Пароли хранятся как PBKDF2, сессия живёт 30 дней,
перебор пароля блокируется.

> Если открываешь лидогенератор в интернет, поставь перед ним HTTPS (nginx или Caddy).
> Внутри локальной сети это не обязательно.

## Как запускать каждый день

Первый раз — `./start.sh` из папки проекта. Дальше удобнее так:

```bash
./start.sh --install
```

Эта команда делает две вещи:

1. **Ярлык «Лидогенератор» в меню приложений** — запуск обычным кликом по значку, без терминала.
   Работает в GNOME, KDE, XFCE и любой другой среде, понимающей ярлыки.
2. **Автозапуск** — спросит, поднимать ли лидогенератор автоматически. Если согласиться,
   он будет стартовать сам при каждом входе в систему, в том числе **после перезагрузки**.
   Root для этого не нужен: служба ставится в профиль пользователя.

```bash
systemctl --user status lidogenerator     # работает ли
systemctl --user stop lidogenerator       # остановить до следующего входа
./start.sh --uninstall                    # убрать ярлык и автозапуск
```

Открывается лидогенератор всегда по одному адресу: **http://127.0.0.1:8765** — можно
просто добавить в закладки браузера.

> Если лидогенератор уже работает (например, его поднял автозапуск), повторный `./start.sh`
> или клик по ярлыку не будут ругаться «порт занят» — они просто откроют окно браузера.

Обновлять при этом ничего не нужно: ярлык запускает `start.sh`, а тот каждый раз сам
проверяет окружение и доустанавливает недостающее.

## Автозапуск на сервере без графики

На сервере, куда никто не входит в графическую сессию, есть два пути.

**Проще:** тот же `./start.sh --install`, а потом разрешить службе работать без входа:

```bash
sudo loginctl enable-linger $USER
```

**Или системная служба** — если лидогенератор должен работать от отдельного пользователя
и стартовать до чьего-либо входа:

```bash
sudo tee /etc/systemd/system/lidogenerator.service > /dev/null <<'EOF'
[Unit]
Description=Лидогенератор
After=network-online.target

[Service]
Type=simple
User=ВАШ_ПОЛЬЗОВАТЕЛЬ
WorkingDirectory=/путь/к/lidogenerator
ExecStart=/путь/к/lidogenerator/start.sh --yes --host 0.0.0.0 --no-browser
Restart=on-failure
RestartSec=10

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl daemon-reload
sudo systemctl enable --now lidogenerator
systemctl status lidogenerator
```

Перед этим обязательно заведи пользователя (`./start.sh --add-user ИМЯ`), иначе сервер
с `--host 0.0.0.0` откажется стартовать.

## Диагностика

```bash
./start.sh --check
```

Покажет одним экраном: версии пакетов, какие ключи есть и **что именно не работает без
каждого недостающего**, остаток кредитов Serper, размер базы, свободен ли порт.

## Если что-то пошло не так

| Что видишь | Что делать |
|---|---|
| `Permission denied` при `./start.sh` | `sh start.sh` |
| `нужен Python 3.10 или новее` и установка не прошла | Поставь вручную: `sudo apt install python3.12 python3.12-venv` (или аналог), затем `./start.sh` |
| `Порт 8765 занят` | `./start.sh --port 8766` |
| Зависимости не ставятся, ошибки сборки | `./start.sh --recreate`; если повторяется — скрипт сам предложит доставить инструменты сборки |
| Окружение сломалось после переноса папки | `./start.sh --recreate` |
| В поиске нет Google Карт, в журнале «через DuckDuckGo» | Кончились кредиты Serper или нет ключа — вкладка «Ключи» |
| `Уже идёт поиск` | Один поиск за раз: дождись или нажми «Остановить» |
| Лидогенератор пропадает после закрытия терминала или перезагрузки | `./start.sh --install` — ярлык в меню и автозапуск при входе в систему |
| Ярлык в меню не появился | Выйти и войти в систему заново (меню кешируется), либо запускать `./start.sh` из папки |

## Обновление

```bash
git pull
./start.sh
```

Если список зависимостей изменился, скрипт увидит это сам (сверяет контрольную сумму
`requirements.txt`) и доставит недостающее. База лидов и ключи не трогаются.

---

## Удаление

```bash
rm -rf /путь/к/lidogenerator      # вместе с базой лидов и ключами
```

Ничего за пределами этой папки лидогенератор не создаёт: ни системных служб (кроме той,
что заведёшь сам), ни файлов в системных каталогах.
