# Roadmap — Лидогенератор

Карта состояния проекта: что сделано, что отложено, что в планах.
Две ниши: **Подоконник ПВХ в размер** и **Сэндвич-панель для откосов в размер**.

---

## ✅ Универсальный режим + веб-интерфейс (сентябрь 2026)

- `python app.py` — локальный веб-интерфейс (`web/index.html` + `parser/webapp.py`, только stdlib).
- Поиск по словам, контексту, сфере (32 пресета, `parser/presets.py`), странам РФ/РБ,
  регионам и городам (`parser/geo.py`).
- Новый источник — **Google Карты через Serper** (`parser/sources/maps.py`): телефон, адрес,
  рубрика, рейтинг без краулинга.
- Универсальная оценка релевантности (`parser/relevance.py`): лёгкий стеммер + покрытие фраз +
  контекст + минус-слова.
- Белорусские телефоны: `+375…` и внутренний `8 0XX …` (раньше превращался в ложный `+70…`).
- Склейка дублей по любому общему телефону или домену (`dedupe.merge_leads`).
- Выдача Serper с `gl=ru/by`, сниппеты в оценке, расширенный стоп-лист агрегаторов (РБ, вакансии,
  отзовики).
- Остановка поиска с сохранением найденного, история поисков, выгрузка фильтра в Excel/CSV.
- Проверка: `python run.py --self-test` (классификатор + телефоны + релевантность).

### Этап 2 — «профи» (сентябрь 2026)
- **База лидов** (`parser/db.py`, SQLite): дедуп между поисками, статусы, менеджеры, комментарии,
  история; вкладка «База» с фильтрами и массовыми действиями.
- **ИИ** (`parser/ai.py`): проверка сайта по смыслу (structured outputs) и подбор запросов.
- **Источники**: Яндекс Карты и 2ГИС через Apify (`ApifyMaps`), Яндекс Поиск API v2
  (`sources/yandex.py`).
- **Контакты** (`parser/contacts.py`): мессенджеры и соцсети, тип номера, MX-проверка почт, УНП.
- **DaData в универсальном режиме**: статус/штат/выручка, отсев ликвидированных, сверка города.
- **Скорость/надёжность**: кеш API (`cache`), Chromium для JS-сайтов (`parser/render.py`), прокси.
- **Автопоиск** по расписанию + Telegram (`parser/notify.py`).
- **CRM** (`parser/crm.py`): Битрикс24 и amoCRM.
- **Команда**: пользователи, вход по паролю, `--host 0.0.0.0`.
- Проверено вживую: Serper, Google Карты, Яндекс Карты (Apify), DaData, Chromium, база, вход.
  Не проверено вживую (нет ключей): Claude, Яндекс Поиск API, Битрикс24/amoCRM, Telegram, 2ГИС.

### Этап 3 (сентябрь 2026)
- **Telegram-каналы** (`sources/telegram.py`): `site:t.me` + публичные страницы t.me; чаты, боты,
  паблики > 50 000 и каналы без ключевых слов в названии/описании отсеиваются. Выход скромный:
  на «натяжные потолки Калуга» — 1 компания из 5 кандидатов (Serper) / 1 из 6 (DuckDuckGo).
- **Serper на нуле**: проверка баланса перед поиском и по ходу, переход на DuckDuckGo, красный
  остаток в шапке при < 200 кредитов.
- Следующий шаг по Telegram — мониторинг чатов на «ищу поставщика…» (Telethon, отдельный аккаунт).

### Этап 4 — переносимость и кредиты (сентябрь 2026)

**Запуск на любой машине с Linux**
- `start.sh` — одна команда на всё: ищет Python 3.10+, собирает `.venv`, ставит зависимости,
  проверяет `.env`, находит Chromium, запускает. Недостающие системные пакеты предлагает поставить
  через apt / dnf / zypper / pacman / apk (с подтверждением, `--yes` — без вопросов).
  Повторный запуск ничего не переставляет: сверка по контрольной сумме `requirements.txt`.
- **Python ставится сам**: системный → пакет из репозитория, сначала версионные имена
  `python3.12`/`python3.11` (в Debian 11 и Ubuntu 20.04 обычный `python3` — это 3.9), с `apt-get update`
  перед установкой на apt.
- **Вкладка «Ключи»** (`parser/keys.py`): все девять сервисов настраиваются из браузера — поле, кнопка
  «Сохранить и проверить», живая проверка ключа (Serper отдаёт остаток кредитов, Apify — план,
  Telegram — имя бота), запись в `.env` и подхват без перезапуска (`config.refresh_keys`).
  Там же написано, что даёт сервис, сколько стоит и где взять ключ.
- **POSIX sh, bash не нужен** — проверено на busybox (то, что стоит в Alpine и минимальных
  контейнерах). Если `venv`/`pip` в системе нет и доставить нечем, работает системным Python
  с `pip --user` и обходом PEP 668 — проверено на питоне с отключённым venv.
- `.env` версионируется вместе с проектом (репозиторий приватный): на новой машине ключи
  появляются сразу после клона, отдельная настройка не нужна.
- `./start.sh --check` и `python app.py --check` (`parser/doctor.py`) — диагностика: версии пакетов,
  какие ключи есть и что именно не работает без каждого, остаток кредитов, база, занятость порта.
- **pandas и numpy убраны** — Excel и CSV пишутся openpyxl и stdlib (`parser/export.py`). Выгрузка
  сверена со старой ячейка в ячейку. Это минус ~100 МБ и главная причина провалов установки
  на musl/редких архитектурах.
- **lxml стал необязательным** (`parser/htmlutil.py`): нет колеса — работаем на `html.parser`.
- Проверено: чистая установка с нуля за 27 с, самопроверка 24/24, сквозной поиск без Serper —
  7 компаний, у всех телефоны.

**Кредиты Serper: деградация вместо обрыва** (политика — без спроса ничего платного не включать)
- Смета сверяется с остатком до старта: «хватит примерно на N запросов из M» — в интерфейсе и в журнале.
- Потолок трат на поиск (`credit_limit`, поле в тонкой настройке): дойдя до него, поиск не встаёт,
  а доходит до конца на бесплатных источниках.
- Лестница: Serper → Google CSE (100 запросов в день бесплатно, если есть ключи) → DuckDuckGo.
  Apify и другие платные источники сами не включаются никогда.
- DuckDuckGo научился отдавать заголовки и сниппеты (раньше терялись — релевантность и ИИ считались
  вслепую) и больше не молчит при троттлинге: бан пишется в журнал, а не выглядит как пустая ниша.

### Этап 5 — читаемость и внешний вид (сентябрь 2026)

- **Контраст проверен цифрами, а не на глаз**: 18 пар «текст на фоне» по WCAG AA в обеих темах.
  Было 4 провала в светлой (серый «низкой релевантности» на белом — 3.2:1 при норме 4.5),
  стало 0 в обеих. В тёмной подписи поднялись с 6.8:1 до 8.0:1.
- **Переключатель темы** в шапке (Авто / светлая / тёмная) вместо жёсткой привязки к системе.
  Тема ставится в `<head>` до отрисовки, поэтому тёмный интерфейс не мигает белым;
  ссылка вида `?theme=dark` открывает нужную тему сразу.
- **Столбец «Статус» перестал кричать**: у всех строк статус «Новый», и синие рамки `select`
  превращали колонку в частокол. Теперь это тихая плашка с мягкой заливкой по смыслу.
- **Мелкий текст подрос**: описания, подсказки и подписи 10–12px → 11–13px, межстрочный 1.45 → 1.5.
  На тёмном фоне тонкие серые буквы «выцветают» сильнее, поэтому приглушённый цвет там светлее.
- Выключенные значки в шапке больше не перечёркнуты полупрозрачным (выглядело как брак) —
  пунктирная рамка. Плейсхолдеры, кольцо фокуса и подсветка строки под курсором стали видимыми.
- Мессенджеры в тёмной теме снова различаются по цвету, вкладка «Ключи» разложена в сетку
  (строки текста были на всю ширину экрана), кнопки перестали растягиваться.

### Этап 6 — город лида определяется честно (сентябрь 2026)

Поиск «сайдинг» по Переславлю-Залесскому показал три бока сразу: в колонке «Где» стояли
Москва, Балашиха и Екатеринбург.

- **Падежи.** Город искался точной формой, а на сайте написано «в ПереславлЕ-ЗалесскОМ» —
  совпадения нет, и город определялся по частоте упоминаний, где побеждает Москва из шапки.
  Теперь названия ищутся по основе слова.
- **Адрес сайта.** `pereslavl-zalesskii.saiding77.ru` прямо называет город, но не учитывался.
  Теперь поддомен, домен и первый сегмент пути разбираются с транслитерацией; короткие
  названия засчитываются только целым словом, «rostov» не выдаётся за Ростов Великий.
  Адрес из карт по-прежнему главнее поддомена.
- **Страна по телефонам**: у сайта с белорусскими номерами больше не может быть страны RU.
- **Пометка «не <город>»** в колонке «Где» и фильтр «только из искомого города»: федеральные
  сайты и чужие филиалы видно сразу. Искомый город хранится вместе со строкой поиска
  (`run_leads.asked`, миграция автоматическая).
- `python app.py --recheck-cities [--apply]` — пересчёт города и страны у накопленной базы.
  На 757 компаниях нашлось 10 ошибок, в том числе «Натяжные потолки в Калуге» с городом Чита.
- Проверено: 8 оффлайн-проверок в самотесте, повторный поиск по тому же запросу (0 кредитов,
  выдача из кеша) и 6 проверок интерфейса в живом браузере.

### Этап 7 — запуск для человека, а не для терминала (сентябрь 2026)

Вопрос с новой машины: «установил из репозитория — а как запускать? а после перезагрузки?»
Ответа не было: `./start.sh` жил только в терминале и умирал вместе с ним.

- `./start.sh --install` — ярлык «Лидогенератор» в меню приложений (`~/.local/share/applications`,
  свой значок `web/icon.svg`) и автозапуск при входе в систему через `systemd --user`.
  Root не нужен. `--uninstall` убирает и то, и другое, не трогая базу лидов.
- Повторный запуск при уже работающем лидогенераторе не падает с «порт занят», а открывает
  окно браузера: клик по ярлыку всегда делает ожидаемое.
- Для сервера без графики — `loginctl enable-linger` либо системный юнит (оба варианта в инструкции).
- Проверено: установка и удаление в песочнице (ярлык и юнит создаются и убираются),
  `desktop-file-validate` и `systemd-analyze verify` без ошибок, определение уже
  запущенного сервера — на живом процессе. Попутно поймана ещё одна ловушка `set -e`:
  неудачный `daemon-reload` обрывал скрипт до сообщения об успехе.

## ✅ Сделано (аудит + фиксы, июнь 2026)

### Качество данных
- **DaData: убраны ложные матчи по названию.** Обогащаем только если: ИНН взят из футера
  сайта (точный поиск) ИЛИ в названии есть различительное слово-бренд, реально встречающееся
  в юрлице. Дженерики («Интернет», «Строительный мир», «Окна») по названию больше не
  привязывают чужие ИНН. Размен в пользу точности: часть лидов остаётся без юр.данных.
- **E-mail: убран мусор.** Почты берём из видимого текста + `mailto:`, а не из всего HTML;
  retina-картинки (`logo@2x.png`) и ассеты (`.css/.js/.svg`) отфильтрованы.
- **Телефоны: ловим слитный формат** `+79991234567` (раньше брались только с разделителями).
- **Имена лидов: больше не заголовки страниц.** `<title>` режем только по сильным
  разделителям (не по внутрисловному дефису — «Интернет-магазин» больше не превращается в
  «Интернет»). Рекламные заголовки («Купить … с доставкой») → подставляем домен.
- **ОКВЭД** выводился кодом — теперь «код + название» (когда DaData отдаёт).
- **Детект города** по границе слова (не считает «Омск» внутри «Омская»).

### Классификатор
- **Stem-матч по началу слова** — «резка» не засчитывается внутри «нарезка» (убрано двойное
  начисление boost).
- **Скоринг переработан** — база 0.40 за прохождение must/any/block; sandwich-лиды
  («сэндвич-панель для откосов в размер») больше не проваливаются в «Под вопросом».
- **Блок-лист расширен**: `сайдинг / дпк / террасн / фасадн` — ДПК-сайдинг и террасная
  доска больше не попадают в подоконники.

### Защита от блокировок
- **Реальный браузерный User-Agent** (вместо палящегося `LeadFinder/1.0`).
- **Заголовки `Accept-Language: ru` и `Accept`** при заходе на сайты.
- Краткий контроль: полный прогон по РФ прошёл с 0 троттлинга Serper и 0 ошибок краулинга.

### Выгрузка (вид для отдела продаж)
- Колонки сокращены до 9: `Название · Тип лида · Уверенность · Город · Телефоны · Почты ·
  Сайт · Источник · Ссылка`.
- Убраны: ИНН, ОГРН, Юр.название, Руководитель, ОКВЭД, Юр.адрес, Адрес, Рубрики,
  Подтв. сайтом, Сработавшие слова.
- Тип лида коротко: `Подоконник` / `Откосы`.

### Чистка кода
- Удалён неиспользуемый `parser/sources/base.py`, выпилен `tenacity`, мёртвые `network.*`
  настройки, stale-`.pyc`.
- README приведён в соответствие с конфигом (нужны ключи Serper/DaData; Apify выключен).
- `run.py`: `--region` поддерживает `auto:NN`.

### Состояние источников
- **Serper** — основной, работает. ~700 кредитов на полный `auto:40`.
- **Apify 2ГИС** — `enabled: false` (актор платный PAY_PER_EVENT, бесплатный план = 403).
- **DaData** — `enabled: false` (юр.данные отделу продаж не нужны).
- **Краулинг сайтов** — работает.

### Последний прогон
- `auto:40`, вся РФ, ~7 мин, 511 лидов: Подоконник 112 · Откосы 176 · Под вопросом 223.
- Телефоны у 90% подоконников.

## 🔜 Отложено (на решение/по запросу)

- **Apify 2ГИС** — включить, если нужен охват по картам с телефонами. Требует: подключить
  биллинг Apify ЛИБО подставить бесплатный 2ГИС-актор в `sources.apify.actor`.
- **DaData** — вернуть юр.данные = `dadata.enabled: true` + вернуть колонки в
  `parser/models.py:COLUMNS`.
- **Транслитерация для DaData** — латинский домен (`Glavsnab.net`) к кириллическому юрлицу
  (`Главснаб`) по названию не наводится; такие тянутся только по ИНН из футера.
- **Фильтр `og:site_name`** — длинные «рекламные» og:site_name (напр. «Интернет магазин ПТК
  УМЕЛЕЦ») сейчас проходят как есть; можно гнать через тот же фильтр «похоже на рекламу → домен».

## 🗺️ Планы / идеи

- **Headless-браузер** для сайтов на чистом JS (Cloudflare-челленджи, контент в браузере) —
  сейчас `requests` их не читает, контакты теряются.
- **Шире охват** — `regions: auto:60` / `auto:80` для большего числа городов.
- **Версионирование** — `git init` (проект пока без истории; `.env` уже в `.gitignore`).
- **Прокси/ротация** — если при расширении охвата начнём ловить лимиты сайтов.
- **Дедуп между прогонами** — копить базу и не выгружать уже обзвоненных.

## 🔐 Безопасность

- В `.env` боевые ключи (Serper/DaData/Apify) — в открытом виде, но под `.gitignore`.
  При шаринге логов/конфига — проротировать.
