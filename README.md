# Лидогенератор

## Запуск на новой машине

```bash
./start.sh            # проверит Python, окружение, зависимости и ключи, доставит недостающее и запустит
```

Подробная инструкция для переноса на другую машину — **[УСТАНОВКА.md](УСТАНОВКА.md)**:
доступ для команды, автозапуск через systemd, разбор типовых проблем.

Если файл не запускается (нет прав) — `sh start.sh`.

Скрипт написан на POSIX sh и **не требует bash** — работает и в Alpine, и в минимальных
контейнерах, где стоит только busybox. Что он делает:

1. ищет Python 3.10+ (перебирает `python3.14 … python3.10`, `python3`, `python`), а если не нашёл —
   ставит из репозитория системы, начиная с **версионных** пакетов (`python3.12`, `python3.11` …),
   потому что в Debian 11, Ubuntu 20.04 и RHEL 9 обычный `python3` — это 3.9 и ниже.
   На apt перед установкой делает `apt-get update`, иначе на свежем контейнере пакет «не найден»;
2. создаёт `.venv` и ставит зависимости; если `venv`/`pip` в системе нет и доставить их нельзя —
   не падает, а работает системным Python с установкой пакетов в домашний каталог
   (включая обход запрета PEP 668 на свежих Debian и Fedora);
3. недостающие системные пакеты предлагает поставить командой для
   **apt / dnf / zypper / pacman / apk** и выполняет её через sudo после подтверждения;
4. если `.env` нет — создаёт из `.env.example`;
5. ищет Chromium (нужен только для сайтов на JavaScript, без него всё остальное работает).

Повторный запуск ничего не переустанавливает: пакеты сверяются по контрольной сумме
`requirements.txt`.

```bash
./start.sh --check              # диагностика: пакеты, ключи, остаток кредитов, база, порт
./start.sh --setup              # только собрать окружение, без запуска
./start.sh --yes                # без вопросов (сервер, CI)
./start.sh --recreate           # пересобрать окружение с нуля
./start.sh --cli --self-test    # нишевый режим (run.py) с его флагами
./start.sh --host 0.0.0.0 --no-browser   # остальные флаги уходят в app.py как есть
```

**Ключи на новой машине.** Два способа, оба без правки файлов вручную:

1. **Вкладка «Ключи»** в самом интерфейсе — вставил ключ, нажал «Сохранить и проверить»:
   ключ уходит в `.env` на сервере, проверяется живым запросом (Serper сразу покажет остаток
   кредитов, Apify — план, Telegram — имя бота) и начинает работать без перезапуска.
   Там же написано, что даёт каждый сервис, сколько стоит и где взять ключ.
2. **`.env` едет вместе с проектом** — он лежит в репозитории, поэтому после `git clone`
   или копирования папки ключи уже на месте. Репозиторий держать приватным.

Разово ключ можно подсунуть и переменной окружения: `SERPER_API_KEY=xxx ./start.sh`.

Без ключей лидогенератор работает, но теряет Google Карты, а это примерно треть компаний —
те, у кого вообще нет сайта, только карточка с телефоном.

**Зависимости** намеренно лёгкие: `pandas`/`numpy` не нужны (Excel пишет openpyxl), а `lxml`
необязателен — если его колесо не соберётся (Alpine/musl, редкая архитектура), HTML разбирает
`html.parser` из стандартной библиотеки.

Два режима:

- **Универсальный, с веб-интерфейсом** (`python app.py`) — любая сфера, свои ключевые слова и
  контекст, Россия и Беларусь, выбор областей и городов. Описан ниже в разделе
  «Универсальный лидогенератор».
- **Нишевый CLI** (`python run.py`) — исходный поиск по двум нишам из `config.yaml`
  (подоконники ПВХ / сэндвич-панели для откосов).

## Универсальный лидогенератор (веб-интерфейс)

```bash
. .venv/bin/activate
python app.py                 # откроет http://127.0.0.1:8765
python app.py --no-browser    # только сервер
```

Страница (`web/index.html`, `web/app.js`, `web/app.css`) отдаётся сервером `parser/webapp.py`.
Ключи API остаются на сервере в `.env` и в браузер не уходят.

### Вкладки
- **Поиск** — форма (что/где/источники/обработка), прогресс с расходами по каждому сервису,
  таблица результатов со статусами, выгрузка Excel/CSV/телефоны/в CRM.
- **База** — все компании из всех поисков в одной базе (`output/leads.db`, SQLite). Повторный
  поиск узнаёт уже найденных (по любому телефону или домену), новые помечены «новая».
  Статусы (Новый → В работе → Созвон → КП → Клиент / Отказ / Не наш), менеджер, комментарий,
  история изменений, массовые действия, выгрузка в CRM.
- **Автопоиск** — сохранённые поиски по расписанию (от 6 часов до недели) + сводка о новых
  компаниях в Telegram. Работает, пока запущен сервер.
- **Карточка компании** (клик по строке) — контакты, мессенджеры, вывод ИИ, юр. данные, история.

### Источники (включаются галочками; без ключа источник серый)
| Источник | Ключ в `.env` | Цена |
|---|---|---|
| Google Карты | `SERPER_API_KEY` | 1 кредит Serper / 10 фирм |
| Яндекс Карты | `APIFY_TOKEN` (актор zen-studio) | ≈ $7 / 1000 фирм, работает на бесплатном плане Apify |
| 2ГИС | `APIFY_TOKEN` (актор m_mamaev) | нужен платный план Apify |
| Сайты из Google | `SERPER_API_KEY` (или DuckDuckGo без ключа) | 1 кредит / 10 ссылок |
| Сайты из Яндекса | `YANDEX_SEARCH_API_KEY` + `YANDEX_FOLDER_ID` | по тарифу Yandex Cloud |
| Telegram-каналы | тот же поисковик, что для Google (Serper или DuckDuckGo) | 1 кредит / 10 ссылок; аккаунт Telegram не нужен |

**Telegram-каналы**: запрос `site:t.me <фраза> <город>`, затем публичные страницы `t.me/<канал>`
(описание, подписчики, последние посты). Выдача там в основном из городских пабликов и СМИ, поэтому
группы/чаты и боты отбрасываются, каналы крупнее `universal.telegram.max_subscribers` — тоже.
Канал и компания из карт с тем же @username склеиваются в одну запись.

**Когда кредиты Serper кончатся.** Платных источников без спроса лидогенератор не включает —
он деградирует на бесплатные и говорит об этом прямо:

- *До старта* смета сверяется с остатком. Если не хватает, под кнопкой появится: «хватит примерно
  на N запросов из M, дальше Google Карты отключатся». Тот же расчёт пишется в журнал поиска.
- *Потолок трат* (тонкая настройка → «Потолок кредитов Serper») останавливает расход на заданной
  сумме: поиск не прерывается, а доходит до конца на бесплатных источниках. Сверяется между
  запросами, поэтому возможен перебор на один запрос.
- *На нуле* сайты и каналы уходят на следующую бесплатную ступень — Google CSE (100 запросов в день,
  если заданы `GOOGLE_CSE_KEY` и `GOOGLE_CSE_CX`), иначе DuckDuckGo. Google Карты отключаются:
  это обычно около половины лидов и большая часть телефонов, поэтому предупреждение громкое.
- DuckDuckGo отдаёт заголовки и сниппеты (релевантность и ИИ не слепнут), а троттлинг больше не
  выглядит как «ниша пустая» — в журнале будет прямое «DuckDuckGo ограничил темп запросов».

Что остаётся бесплатным: DuckDuckGo (или Google CSE), обход сайтов, кеш на 7 дней, Яндекс Карты
через Apify в пределах бесплатных $5 в месяц (≈ 700 компаний) — но Apify сам не включается.

### Обработка
- **Обход сайтов** — телефоны, почты, мессенджеры (Telegram, WhatsApp, Viber, VK, Instagram, OK),
  город, ИНН/УНП. Сайты на JavaScript дорендериваются через headless Chromium (ищется сам,
  путь можно задать в `config.yaml → universal.render`). Прокси — `universal.proxies`.
- **Проверка почт** — адреса с несуществующим почтовым доменом (нет MX/A-записи) отбрасываются.
- **ИИ-проверка** (`ANTHROPIC_API_KEY`) — Claude читает сайт и описание «кого ищем»: подходит или
  нет, тип компании (производитель / магазин / услуги / каталог…), причина, услуги. Каталоги,
  агрегаторы и СМИ получают низкую оценку. Кнопка «✨ Подобрать ИИ» дописывает запросы,
  контекст и минус-слова. Модель по умолчанию `claude-opus-5`; дешевле —
  `claude-sonnet-5` / `claude-haiku-4-5` в `config.yaml → universal.ai.model`.
- **Юр. данные РФ** (`DADATA_API_KEY`) — ИНН, юрлицо, статус, штат, выручка. Ликвидированные и
  банкроты отсеиваются. По названию сопоставляем только при совпадении города.
- **Кеш** — ответы Serper, Яндекса и Apify хранятся 7 дней (`universal.cache_days`): повтор
  поиска не тратит ни кредитов, ни денег.

### CRM и Telegram
- Битрикс24: `BITRIX24_WEBHOOK` (входящий вебхук с правом crm) → лиды через `crm.lead.add`.
- amoCRM: `AMOCRM_HOST` + `AMOCRM_TOKEN` (долгосрочный токен) → сделки с компанией через `leads/complex`.
- Telegram: `TELEGRAM_BOT_TOKEN` + `TELEGRAM_CHAT_ID`; `APP_PUBLIC_URL` — ссылка в уведомлении.

### Для команды (доступ по сети)
```bash
python app.py --add-user ivan          # завести пользователя (пароль спросит), вход включится сам
python app.py --host 0.0.0.0 --no-browser
```
Без пользователей сервер наружу не запустится. Пароли — PBKDF2, сессия — HttpOnly-cookie на 30 дней,
защита от перебора. Для работы через интернет поставь перед сервером HTTPS (nginx/Caddy) и
запускай как сервис (systemd), чтобы автопоиск работал постоянно.

**Что задаёшь:**
- **Сфера деятельности** — 32 пресета (стройка, автосервисы, медицина, IT, общепит, логистика…).
  Пресет подставляет запросы, контекст и минус-слова — всё можно править.
- **Ключевые слова** — фразы для поиска и карт (по одной на строку), город подставляется сам.
- **Контекст** — свободное описание нужной компании. Эти слова ищем на её сайте: чем больше совпало,
  тем выше релевантность.
- **Минус-слова** — слово в названии, заголовке или рубрике отсеивает лид.
- **Страны и регионы** — Россия (83 субъекта) и Беларусь (Минск + 6 областей). Охват внутри
  региона: только центр или все крупные города. Плюс поле «Свои города» для любых других.
  Справочник — `parser/geo.py`. Без регионов поиск идёт по стране целиком.
- **Источники** — Google Карты (через Serper `/places`: телефон, адрес, рубрика, рейтинг) и сайты
  из поисковой выдачи. Плюс опция «заходить на сайты»: почты, телефоны, город и проверка контекста.

**Что получаешь:** таблицу с релевантностью 0–100, фильтрами (релевантность, страна, регион,
источник, с телефоном/почтой, текст), сортировкой. Выгрузка текущего фильтра в Excel/CSV,
копирование телефонов. Каждый поиск сохраняется в `output/runs/*.json` (кнопка «История») и
`output/leads_*.xlsx`.

**Релевантность** (`parser/relevance.py`): покрытие ключевых фраз в «шапке» компании (название,
заголовок сайта, описание, рубрика) и на сайте + доля слов контекста на сайте. Компании из Карт
получают стартовый бонус: Карты сами отдали их по запросу. Телефоны РБ приводятся к `+375…`
(в том числе внутренний формат `8 0XX …`), РФ — к `+7…`.

**Расход Serper:** 1 кредит за страницу выдачи (10 ссылок) и 1 кредит за страницу Карт.
Перед запуском интерфейс показывает смету и баланс. Пример: 1 фраза × 1 город, Карты + 10 ссылок
≈ 2–3 кредита.

## Нишевый режим (CLI)

Ищет компании-лиды по двум направлениям и раскладывает их по типам:

1. **Подоконник ПВХ в нарезку / в размер** — продают или сами пилят подоконники ПВХ по точному размеру.
2. **Сэндвич-панель для откосов в размер** — пилят и продают сэндвич-панели для откосов.

## Как устроено

Официальный API 2ГИС закрыт партнёркой, бесплатный Яндекс.XML закрыт — поэтому собираем лиды
из нескольких источников и сводим в один поток:

```
                  ┌─ SERP (Serper) ──────► сайты компаний ─┐
запросы × города ─┤                                        ├─► краулинг сайтов ─► классификатор ─► DaData ─► Excel+CSV
   (config.yaml)  └─ 2ГИС (через Apify) ─► фирмы+телефоны ──┘   (контакты,город,    (тип лида+     (ИНН,ОГРН,
                                                                подтв. ниши)        уверенность)   ОКВЭД,рук.)
```

**Источники (включаются в `config.yaml → sources`):**
- **search (Serper)** — ищем сайты по нишевым запросам по всей РФ. Маркетплейсы/соцсети/карты отсеиваются.
- **apify (2ГИС)** — парсер 2ГИС через Apify (`m_mamaev/2gis-places-scraper`): фирмы с телефонами/сайтами/рубриками.
  Это обход партнёрского API 2ГИС.

**Обработка:**
- **Краулинг** — заходим на сайт (главная + контакты + о компании + услуги + каталог), тащим
  **телефоны, e-mail, город**, и **подтверждаем нишу**: на сайте есть и целевой материал
  (подоконник ПВХ / сэндвич / откос), и признак «режут в размер» (нарезка/распил/в размер/под заказ).
- **Классификатор** — скоринг по ключевым словам с блок-листом (отсекает деревянные подоконники,
  кровельные/фасадные панели и т.п.). Подтверждение сайтом повышает уверенность.
- **DaData** — каждому лиду выше порога подтягивает ИНН/ОГРН/ОКВЭД/руководителя/юр.адрес.
- **Дедуп** — по телефону и домену, контакты сливаются.
- Уверенность ниже порога → вкладка **«Под вопросом»** для ручной проверки.

## Установка и запуск

```bash
cd Лидогенератор
./start.sh --setup            # или вручную: python3 -m venv .venv && pip install -r requirements.txt
cp .env.example .env          # и вписать ключи (см. ниже)

python run.py                 # вся Россия (regions: auto:40), по config.yaml
python run.py --region Москва # только один регион
python run.py --region auto:60 # топ-60 городов
python run.py --self-test     # проверить классификатор без сети
```

**Ключи.** Поставляемый `config.yaml` использует два источника, каждому нужен ключ в `.env`:
`SERPER_API_KEY` (поиск сайтов) и `DADATA_API_KEY` (юр.данные). Без ключей источник сам
отключится с предупреждением. Хочешь совсем без ключей — переключи `sources.search.backend`
на `duckduckgo` и выставь `dadata.enabled: false`.

**2ГИС через Apify выключен по умолчанию** (`apify.enabled: false`): актор
`m_mamaev/2gis-places-scraper` платный (PAY_PER_EVENT), и бесплатный аккаунт Apify его не
запускает — отдаёт HTTP 403. Включай только с подключённым биллингом Apify либо подставь
бесплатный 2ГИС-актор в `sources.apify.actor`.

Результат — в `output/`: `leads_<дата>.xlsx` (вкладки по типам + «Под вопросом») и CSV по каждому типу.

## Настройка — всё в `config.yaml`

- `regions` — охват:
  - `"auto:40"` — топ-40 городов РФ из встроенного списка (для «всей России» ставь `auto:60`…`auto:80`);
  - `[]` — один общероссийский проход (быстро, но узко);
  - список городов — ровно эти.
- `queries` — поисковые запросы (нишевые, с покупательским интентом). Город подставляется автоматически.
- `lead_types` — правила классификации (`must` / `any` / `boost` / `block`). Нужен 3-й тип лида —
  добавь блок по аналогии.
- `score_threshold` — порог «чистый лид» vs «Под вопросом».
- `sources.search` — бэкенд, глубина выдачи (`results_per_query`), потолок доменов (`max_sites`),
  пауза между поисками (`request_delay`).
- `sources.apify` / `sources.dadata` — включение 2ГИС и обогащения юр.данными (нужны ключи).

## Бэкенды поиска

`config.yaml` по умолчанию использует `serper`. Альтернативы переключаются в
`sources.search.backend`; ключи — в `.env` (см. `.env.example`):

| backend       | ключи                         | заметки                                   |
|---------------|-------------------------------|-------------------------------------------|
| `serper`      | `SERPER_API_KEY`              | по умолчанию, результаты Google, дёшево    |
| `duckduckgo`  | не нужны                      | бесплатно, но капризен к темпу, ~10–30/запрос |
| `google_cse`  | `GOOGLE_CSE_KEY` + `..._CX`   | 100 запросов/день бесплатно               |
| `yandex_xml`  | `YANDEX_XML_USER` + `..._KEY` | Яндекс XML                                |

При отсутствии нужного ключа бэкенд автоматически откатывается на DuckDuckGo.

> **Расход Serper.** При `auto:40` это 240 запросов × ~3 страницы ≈ 700 кредитов за прогон —
> учитывай лимит. Меньше городов (`auto:NN`) или `results_per_query` снижают расход.

## Известные ограничения

- Сайты на чистом JS (контент рисуется в браузере) краулер `requests` не прочитает — контакты с них
  не извлекутся. Лечится подключением headless-браузера (добавлю по запросу).
- Город на мультигородних сайтах определяется по частоте упоминания — иногда промахивается;
  проверяй колонку «Город» на спорных.
- DuckDuckGo при частых запросах может временно ограничивать — увеличь `request_delay` или возьми ключ.
